# Деплой на сервер

Продакшен-обвязка поверх обычного `docker-compose.yml`. Для запуска у жюри она не нужна: там по-прежнему `docker compose up --build`.

```
интернет ─▶ nginx :8080 (HTTP) / :8443 (HTTPS) ─▶ app :8080 ─▶ db (Postgres)
                     └─ /grafana/ ─▶ grafana ─▶ prometheus ◀─ node-exporter, cadvisor, blackbox
```

Порты 80 и 443 на сервере занимает другой проект, поэтому наш вход — 8080 и 8443 (`HTTP_PORT` и `HTTPS_PORT` в `.env`). Наши ресурсы изолированы: compose-проект `odin-zapros`, каталог `~/odin`, юниты `odin-cd.*`. Чужие контейнеры, VPN и порты мы не трогаем.

## Установка (один раз)

```bash
git clone https://github.com/ostrovok-hackathon-2026/5-ukazatelei.git ~/odin
~/odin/deploy/bootstrap.sh
```

Скрипт создаёт `.env`: внешний IP, порты и случайный пароль Grafana. Затем включает таймер CI/CD и делает первую выкатку. Ключ LLM нужно вписать в `~/odin/.env` (`LLM_*`), без него агент работает в офлайн-режиме.

Порты 8080 и 8443 должны быть открыты в фаерволе GCP, например так:
`gcloud compute firewall-rules create odin-web --allow tcp:8080,tcp:8443 --target-tags http-server`.

## CI/CD

GitHub Actions в организации хакатона не запускаются, поэтому конвейер работает на сервере (pull-модель, `deploy/cd.sh`). Таймер `odin-cd.timer` раз в 2 минуты:

1. Делает `git fetch` ветки `main`. Если коммит новый, продолжает.
2. **CI:** собирает тестовый образ (`--target test`) и прогоняет `pytest`. Красный коммит не выкатывается.
3. **CD:** собирает образ `odin-zapros/app:<sha>` и делает `docker compose up -d`.
4. Проверяет `/health` через nginx (до 90 с). При сбое откатывается на предыдущий коммит и образ.
5. Оставляет 3 последних образа, остальные удаляет.

Журнал выкаток лежит в `deploy/cd.log`, выкаченный коммит — в `deploy/.deployed`, сломанный — в `deploy/.failed`.

```bash
~/odin/deploy/cd.sh --force          # выкатить вручную
systemctl status odin-cd.timer       # таймер
tail -f ~/odin/deploy/cd.log         # журнал
```

## Мониторинг

Grafana: `http://<IP>:8080/grafana/`, логин `admin`, пароль `GRAFANA_PASSWORD` из `.env`. Дашборд «О!дин запрос — обзор» показывает:
- доступность и время ответа сайта: blackbox проверяет `/health`, `/api/status` и `/`;
- CPU, память и диск сервера (node-exporter);
- CPU, память и время работы наших контейнеров (cAdvisor).

Prometheus хранит данные 7 дней (не больше 1 ГБ) и наружу не открыт. У каждого сервиса стоит лимит памяти, весь стек укладывается примерно в 1,9 ГБ. Логи контейнеров ротируются по 10 МБ × 3.

## Сертификаты

- **Сейчас (по IP):** самоподписанный сертификат на 365 дней, его создаёт `certs-init` при первом запуске. Браузер покажет предупреждение — для IP это нормально.
- **С доменом:** `deploy/certs.sh <домен> <email>` выпускает сертификат Let's Encrypt через DNS-проверку (порт 80 занят, HTTP-проверка невозможна). Скрипт кладёт сертификат в volume `certs` и перезагружает nginx без простоя. После этого впишите `PUBLIC_HOST=<домен>` в `.env`.

## Безопасность

- `app` и `db` наружу не открыты, вход только через nginx.
- Заголовки `nosniff`, `SAMEORIGIN`, `Referrer-Policy`.
- Лимит 10 запросов в секунду к агенту с одного IP.
- Регистрация в Grafana выключена.
- Секреты лежат только в `.env` на сервере, в git их нет.
